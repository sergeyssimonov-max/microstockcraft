# microstockcraft.com – аудит и план доработки

Дата аудита: 28.10.2026. Ревизия: `37e4d59` (ветка `main`).
Методика: полное чтение кода (5 HTML, 1 CSS, служебные файлы), бинарная проверка ассетов (хеши, метаданные шрифтов и изображений), рендер в Chromium (1280, 375, 320 px), расчет контраста по WCAG 2.1, сверка живого сайта, фактчек 35 внешних сервисов и NZ-правовых утверждений по состоянию на октябрь 2026 года.

Сильные стороны: валидная разметка (все теги закрыты), нет горизонтального скролла ни на одной ширине, самохостинг шрифтов без внешних запросов, токены цветов, touch-target 44 px, `focus-visible`, единый OG/Twitter/JSON-LD набор, вес страницы около 300 КБ. Фундамент годный. Проблемы ниже – в содержании, ассетах, доступности и сопровождении.

Шкала: **P0** – публичный дефект, чинить немедленно. **P1** – заметно портит качество или SEO. **P2** – полировка. **P3** – развитие.

## 2. Ассеты и производительность (P1)

| № | Дефект | Факт / решение |
|---|---|---|
| 1.1 | Дубли шрифтов, лишние ~75 КБ трафика | `archivo-700` ≡ `archivo-800` и `ibmplexsans-400` ≡ `ibmplexsans-600` (одинаковые хеши). Это **вариативные** шрифты (Archivo wght 100–900, Plex Sans 100–700), по имени файлов – статические. Браузер грузит каждый файл дважды под разными URL (подтверждено в рендере). Решение: по одному файлу на семейство, один `@font-face` с `font-weight: 100 900` / `100 700`. |
| 1.2 | В шрифтах нет макронов te reo Māori | Ни один из трех субсетов не содержит ā ē ī ō ū Ā. Для NZ-локализации это блокер: «Māori», «Tāmaki Makaurau», «Ōtautahi» отрисуются fallback-шрифтом. Сейчас макронов в тексте нет – что само по себе ошибка локализации (см. 4.3). Решение: пересобрать субсеты с `U+0100-017F` (Latin Extended-A) или хотя бы `U+0100,0101,0112,0113,012A,012B,014C,014D,016A,016B`. |
| 1.3 | Нет глифа → (U+2192) | Стрелки в индексе главной и в кнопке «CHAT ON LINKEDIN →» рендерятся системным шрифтом. Добавить в субсет или заменить на inline SVG. |
| 1.4 | Нет `width`/`height` у изображений | `researcher.jpg` и сетка портфолио – CLS. Плюс нет `loading="lazy"`/`decoding="async"`, нет WebP/AVIF и `srcset`. |
| 1.5 | Нет `<link rel="preload">` для шрифта заголовков | FOUT на hero. Preload только Archivo (один файл после 1.1). |
| 1.6 | Кэш CSS «immutable на год» без фингерпринта | `htaccess`: `max-age=31536000, immutable` для `style.css`. Любая правка стилей не дойдет до вернувшихся посетителей год. Либо `style.css?v=YYYYMMDD` / `style.<hash>.css`, либо убрать `immutable` для CSS. |
| 1.7 | `htaccess` без точки | Файл не активен ни на Apache, ни на GitHub Pages. Решить, где хостинг (в репозитории нет `CNAME` – требует проверки, как домен привязан), и либо переименовать в `.htaccess`, либо удалить и перенести заголовки в `_headers` (Netlify/Cloudflare Pages). |
| 1.8 | OG-картинка в чужой гарнитуре | `og-image.png` набран DejaVu Sans, а не Archivo/Plex, логотип-диафрагма не совпадает с favicon. Пересобрать в фирменных шрифтах; для подстраниц – отдельные OG. |

## 4. Контент и фактура (P1)

### 4.1. Противоречия в позиционировании
- «A decade of selling stock» при «since 2009» – это 17 лет. Либо «Seventeen years…», либо без числа.
- Главная обещает «Field notes» и «tips», раздел `articles.html` называется «articles», анонс – «the NZ Photo directory». Ни заметок, ни статей, ни директории на сайте нет: это три списка ссылок. Либо переименовать (`nz.html`, «NZ resources»), либо реально написать 3–5 материалов.
- Eyebrow «MICROSTOCKCRAFT TODAY» ничего не сообщает.
- H1 «Facts and faces» на странице без единого лица.

### 4.3. NZ-локализация – слабое место
- Ни одного макрона, хотя тематика – Aotearoa. Как минимум: Māori, te reo Māori.
- Нет ключевых живых NZ-ресурсов: NZIPP и Iris Awards (`nzipp.org.nz`), PSNZ как организация (`photography.org.nz` – есть только журналы), PhotoForum NZ (`photoforum-nz.org`), WeCreate (`wecreate.org.nz`), One Shot (`oneshot.co.nz` – проверить и снять метку discontinued).
- Книжные ссылки ведут на amazon.co.uk и amazon.com вперемешку, все по `http://`. Для NZ-аудитории – единообразно `amazon.com.au` или нейтрально через ISBN (Open Library / Google Books).
- Нет тем, которые в 2026 году определяют микросток: политика генеративного ИИ у Adobe Stock/Shutterstock/Getty, раскрытие AI-контента, биометрические релизы Getty (март 2026), C2PA/Content Credentials. «Bookshelf» застрял в 2008–2014 годах («2014 Photographer's Market»).

### 4.4. Гигиена ссылок
- 30 ссылок по `http://` – перевести на `https://`.
- `itunes.apple.com/nz/app/...` (40+ шт.) – устаревший домен, заменить на `apps.apple.com/nz/app/...`.
- Discontinued-пункты без ссылок – давать ссылку на снимок Wayback Machine: каталог становится архивом отрасли, а не кладбищем имен.
- Три книги без ссылок и без статуса (Rasmussen, Nicole Young «(micro)STOCK», Matt Wright) – дать ISBN-ссылку.
- Копирайт «2009—2026» – диапазон в английском набирается en dash: «2009–2026».

## 5. SEO и метаданные (P1–P2)

- `<meta name="keywords">` – мертвый сигнал, удалить.
- JSON-LD одинаковый на всех страницах. Добавить `BreadcrumbList`, для каталогов – `ItemList`, для `about.html` – `ProfilePage` + расширенный `Person` (`knowsAbout`, `image`).
- `og:type` везде `website`; OG-картинка одна на сайт.
- `sitemap.xml`: всем страницам `lastmod 2026-06-21`; обновлять автоматически при сборке. `changefreq`/`priority` Google игнорирует – можно удалить.
- Нет `404.html`.
- Нет `README.md`, `LICENSE`, политики приватности (сайт без аналитики – это стоит прямо заявить одной строкой в футере как преимущество).
- Футер `articles.html` без соцссылок – выбивается из остальных четырех страниц.

## 6. Архитектура и сопровождение (P2)

- 5 страниц дублируют `<head>`, шапку, футер и JSON-LD вручную; ~120 пунктов каталога – ручной HTML. Любая правка навигации или статуса – пять файлов. Коммиты «Add files via upload» показывают правку через веб-интерфейс GitHub.
- Ограничение проекта: JS только ванильный, Node.js не применяется. Сборщик не вводится, страницы остаются рукописным HTML. Риск рассинхрона шапки и футера закрывается чек-листом правок и проверкой в CI (см. раздел 7).
- Поле `checked: YYYY-MM-DD` у каждого пункта + визуальное «verified Oct 2026» в каталоге – это главный аргумент доверия для справочника.

## 7. Контроль качества (P2)

GitHub Actions на каждый push + еженедельно по cron, без Node.js:
- W3C Nu HTML Checker (`vnu.jar`) – разметка;
- `lychee` (готовый бинарник) – битые и редиректящие ссылки, отчет в issue;
- проверка дублей ассетов по хешу shell-скриптом (поймала бы 1.1 и 0.1);
- доступность и Lighthouse – вручную перед релизом (Chrome DevTools), чек-лист в README.

## Допущения и что требует проверки
- Хостинг: по DNS microstockcraft.com указывает на 31.31.197.125 (диапазон REG.RU, Apache). GitHub Pages не используется, слияние в `main` само по себе сайт не обновляет: публикация – через `.github/workflows/deploy.yml` (FTP-секреты задает владелец).
